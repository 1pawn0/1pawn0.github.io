### Coordinate List (COO)

**`edge_index`** matrix is a 2D tensor of shape **`[2, num_edges]`** that stores the indices of the source and target nodes for each edge in a graph.  

- Row 0 (Top Row): Contains the Source Nodes (where the directed edge starts).
- Row 1 (Bottom Row): Contains the Target Nodes (where the directed edge ends).

# An Introduction to Heterogeneous Graphs

## 1. What Are Heterogeneous Graphs?

A **heterogeneous graph** (heterograph) is a graph that contains multiple types of nodes and/or multiple types of edges.

A traditional graph is usually **homogeneous**:

[
G=(V,E)
]

where:

* (V) represents a single type of node.
* (E) represents a single type of relationship.

For example, a social network can be modeled as:

```
Person ---- follows ---- Person
```

However, many real-world systems contain different entities and relationships:

* A research network contains **authors**, **papers**, and **venues**.
* An e-commerce network contains **users**, **products**, and **categories**.
* A transportation network contains **stations**, **roads**, and **vehicles**.

These systems are better represented as heterogeneous graphs.

A heterogeneous graph can be described as:

[
G=(V,E,\tau,\phi)
]

where:

* (V) is the set of nodes.
* (E) is the set of edges.
* (\tau(v)) assigns a node type to each node.
* (\phi(e)) assigns an edge type to each edge.

---

## 2. Why Use Heterogeneous Graphs?

Different node and edge types often have different meanings.

For example, in an academic network:

```
Author --writes--> Paper
Paper --published_in--> Venue
Author --collaborates_with--> Author
```

The relationship `writes` is fundamentally different from `collaborates_with`.

A homogeneous graph representation would lose this semantic information:

```
Node ---- connects_to ---- Node
```

A heterogeneous graph preserves:

* Entity types.
* Relationship semantics.
* Different feature spaces.
* Different message-passing behaviors.

This additional structure allows graph neural networks (GNNs) to learn more meaningful representations.

---

## 3. Heterogeneous Graphs in PyTorch Geometric

PyTorch Geometric represents heterogeneous graphs using:

```python
torch_geometric.data.HeteroData
```

`HeteroData` stores:

* Node features for each node type.
* Edge indices for each relation type.
* Edge features.
* Labels and other graph attributes.

A heterogeneous graph is organized using **node types** and **edge types**.

An edge type is represented as a triplet:

```
(source_node_type, relation_type, destination_node_type)
```

For example:

```python
("author", "writes", "paper")
```

means:

```
author --writes--> paper
```

---

# 4. Basic HeteroData Example

Consider a small academic graph:

```
Alice --------writes--------> Paper1
Bob ----------writes--------> Paper2

Paper1 ----published_in----> Conference
Paper2 ----published_in----> Journal
```

There are three node types:

* `author`
* `paper`
* `venue`

and two edge types:

* `author writes paper`
* `paper published_in venue`

## Creating the Graph

```python
import torch
from torch_geometric.data import HeteroData

data = HeteroData()
```

---

## 5. Adding Node Types

Each node type has its own feature matrix.

For authors:

```python
data["author"].x = torch.tensor([
    [1, 0],
    [0, 1]
], dtype=torch.float)
```

For papers:

```python
data["paper"].x = torch.tensor([
    [0.5, 0.8],
    [0.2, 0.4]
], dtype=torch.float)
```

For venues:

```python
data["venue"].x = torch.tensor([
    [1.0, 0.5],
    [0.3, 0.9]
], dtype=torch.float)
```

The feature dimensions do not have to be the same.

---

## 6. Adding Edge Types

Edges are stored using `edge_index`.

The `writes` relation:

```
author --> paper
```

```python
data["author", "writes", "paper"].edge_index = torch.tensor([
    [0, 1],
    [0, 1]
])
```

Meaning:

```
author 0 --> paper 0
author 1 --> paper 1
```

The `published_in` relation:

```
paper --> venue
```

```python
data["paper", "published_in", "venue"].edge_index = torch.tensor([
    [0, 1],
    [0, 1]
])
```

Meaning:

```
paper 0 --> venue 0
paper 1 --> venue 1
```

---

## 7. Inspecting HeteroData

Printing the graph:

```python
print(data)
```

Example output:

```
HeteroData(
  author={ x=[2,2] },
  paper={ x=[2,2] },
  venue={ x=[2,2] },
  (author, writes, paper)={ edge_index=[2,2] },
  (paper, published_in, venue)={ edge_index=[2,2] }
)
```

Accessing node types:

```python
print(data.node_types)
```

Output:

```
['author', 'paper', 'venue']
```

Accessing edge types:

```python
print(data.edge_types)
```

Output:

```
[
 ('author', 'writes', 'paper'),
 ('paper', 'published_in', 'venue')
]
```

# 8. Message Passing in Heterogeneous GNNs

In a homogeneous GNN, messages are aggregated from neighbors:

[
h_v^{(k+1)}
===========

f(h_v^{(k)},{h_u^{(k)}:u\in N(v)})
]

In heterogeneous graphs, each relation has its own transformation:

[
h_v^{(k+1)}
===========

\sum_r
AGG_r
(
W_r h_u^{(k)}
)
]

where:

* (r) represents an edge type.
* (W_r) is a relation-specific weight matrix.

For example:

```
Author --writes--> Paper
```

may use different parameters from:

```
Paper --published_in--> Venue
```

because the relationships have different meanings.

---

# 9. Converting a GNN Model to Heterogeneous Form

PyTorch Geometric provides utilities such as:

```python
torch_geometric.nn.to_hetero
```

to convert a normal GNN into a heterogeneous GNN.

Example:

```python
from torch_geometric.nn import GCNConv, to_hetero

model = GCNConv(16, 32)

hetero_model = to_hetero(
    model,
    data.metadata()
)
```

The metadata contains:

```python
data.metadata()
```

which returns:

```python
(
    ['author', 'paper', 'venue'],
    [
        ('author', 'writes', 'paper'),
        ('paper', 'published_in', 'venue')
    ]
)
```

The converted model automatically learns separate parameters for different node and edge types.

# Summary

A heterogeneous graph extends ordinary graphs by allowing:

* Multiple node types.
* Multiple edge types.
* Different feature spaces.
* Relation-specific learning.

In PyTorch Geometric, `HeteroData` provides a natural representation:

```python
data[node_type].x
data[source, relation, destination].edge_index
```

This structure preserves the semantics of complex real-world networks and enables specialized heterogeneous graph neural networks.
